Instromen & doorgroeien

Vier werkprofielen, één basis.

De kleur geeft de typische technische zwaarte aan, geen status of absolute rangorde. Een ervaren developer bij een webagency kan complexer werk doen dan een junior bij een productbedrijf. De vraag is: welk type werk en welke breedte of diepte kom je daar meestal tegen?

🟢 LAAG–MIDDEN

1. Web & CMS

laagdrempelige instroom

Webagencies, digitale bureaus, websites, WordPress/CMS, eenvoudige e-commerce en weboplossingen. Toegankelijk voor een starter; niet iedere agency bouwt alleen eenvoudige sites.

Technische eindleerdoelen

Fundamentals die je kunt laten zien.

Deze doelen sluiten aan op het SBB-dossier: technisch ontwerpen, software realiseren, testen en verbetervoorstellen doen. Ze vertalen dat naar concrete, toetsbare technische opbrengsten op mbo-4-niveau.

01 — Programmeren

Ontwerpt, implementeert, test en debugt programma's met functies, control flow, datastructuren, algoritmisch denken, foutafhandeling en passende programmeerconstructies.

02 — Objecten & codekwaliteit

Past objectgeoriënteerde principes toe waar passend, deelt code op in begrijpelijke componenten en verbetert leesbaarheid, hergebruikbaarheid en onderhoudbaarheid.

03 — Van requirement naar ontwerp

Vertaalt gebruikers- en systeemeisen naar user flows, acceptatiecriteria, een technisch ontwerp en afgebakende taken; onderbouwt gemaakte keuzes.

04 — Relationele data

Ontwerpt een relationeel datamodel, voert CRUD-operaties met SQL uit, past relaties en constraints correct toe en herkent eenvoudige performanceproblemen.

05 — Web fundamentals

Bouwt toegankelijke, responsive interfaces met HTML, CSS en JavaScript en legt uit hoe browser, HTTP en client/server samenwerken.

06 — API's & integratie

Gebruikt én ontwikkelt een REST API met routing, JSON request/response-data, validatie, foutafhandeling, documentatie en authenticatie.

07 — Git teamwork

Werkt met Git via betekenisvolle commits, branches, pull requests en code review; lost eenvoudige merge-conflicten zorgvuldig op.

08 — Testen & regressie

Schrijft en voert unit- en integratietests uit voor kritieke functionaliteit, maakt code testbaar en voorkomt regressies bij wijzigingen.

09 — Debugging & observability

Onderzoekt fouten reproduceerbaar met IDE/devtools, logs en tests; lokaliseert de oorzaak, herstelt die en verifieert de oplossing.

10 — Secure by default

Past inputvalidatie, authenticatie, autorisatie, veilig secretsbeheer en basis-OWASP-principes toe; behandelt privacygevoelige data bewust.

11 — Deploy & onderhouden

Levert een applicatie buildbaar en deploybaar op, gebruikt hosting en basis-CI/CD bewust en kan bestaande code lezen, aanpassen, testen en documenteren.

12 — Zelfstandig leren

Onderzoekt een nieuwe taal, library of tool aan de hand van documentatie, bouwt een klein bewijs van werking en legt de keuze en beperkingen uit.

Drie soorten kennis

Een framework is een middel, geen einddoel.

Werkgevers noemen stacks en tools in vacatures. Dat zijn context en voorbeelden — geen vervanging voor programmeerfundamentals. Het opleidingseindpunt is een developer die een gekozen technologie verantwoord kan inzetten én de volgende kan leren.

A — MOET BEHEERSEN

Zelfstandig toepassen

Programmeren · Git · SQL · debugging · API gebruiken/bouwen · testen · basis security · HTML/CSS/JS.

B — MOET BEGRIJPEN

Concept en toepassing

Basisarchitectuur · CI/CD · cloudconcepten · containerbegrip · schaalbaarheid · authentication flows. Geen specialistische beheerseis.

C — MOET KUNNEN LEREN

Nieuwe technologie oppakken

React · Vue · Angular · .NET · Spring · Django · FastAPI · Node.js · cloudplatformen. Kies een stack om mee te bouwen, maar toets het leervermogen.

“De student begrijpt component-based frontendontwikkeling en kan zelfstandig een gekozen frontend-framework leren en toepassen.”

Bewijs in één geheel

Eindproject: een echte full-stack applicatie.

Bijvoorbeeld: een reserveringsplatform voor een lokale organisatie. Geen verzameling tutorials, maar één afgebakend product dat de technische keten zichtbaar maakt.

01 Requirements, user stories, acceptatiecriteria en technische analyse

02 Datamodel + SQL, frontend, backend en gedocumenteerde REST API

03 Login, rollen/autorisatie, validatie, foutafhandeling en veilig secretsbeheer

04 Git-flow, pull requests, tests, debugging, logging, deployment en gebruikersfeedback

TRACEABILITY

Wat laat het project aantoonbaar zien?

Bouwen
Interface, businesslogica, data en API werken samen.

Begrijpen
Ontwerpkeuzes, HTTP, authenticatie en datastromen zijn uitlegbaar.

Kwaliteit leveren
Tests, foutafhandeling en debugging voorkomen 'werkt alleen bij mij'.

Onderhouden
Documentatie, Git en leesbare code maken overdracht en verbetering mogelijk.

Leren
Een nieuwe library of framework wordt bewust gekozen en onderbouwd.
